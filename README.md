# Marker QC

Marker QC — настольное приложение для измерения изогнутых маркеров через USB/UVC-микроскоп. Приложение непрерывно показывает пять измерительных точек, длину, ширину и итог **ДА/НЕТ**, но сохраняет один согласованный кадр только по кнопке **ИЗМЕРИТЬ**.

Нормы: длина 7,00 ± 0,10 мм, ширина 1,15 ± 0,05 мм. Решение рассчитывается по неокруглённым значениям. Ошибка распознавания не считается результатом НЕТ.

## Windows: готовое приложение

1. Откройте раздел **Releases** репозитория и скачайте последний файл `MarkerQC-Windows-x64.zip`.
2. Распакуйте ZIP полностью.
3. Запустите `MarkerQC\MarkerQC.exe`.
4. Не удаляйте каталог `_internal` и не переносите отдельно один EXE: это onedir-приложение.
5. Подключите микроскоп, выберите камеру и разрешение, нажмите **Подключить**.
6. При необходимости выполните **Калибровку** по двум точкам эталона. Расстояние по умолчанию — 10,00 мм, но его можно изменить.
7. Нажмите **Область поиска** и выделите часть кадра с маркером, исключив калибровочную полоску и оснастку. Кнопка **Весь кадр** сбрасывает ограничение.
8. Проверьте точки и нажмите **ИЗМЕРИТЬ**. История поддерживает CSV, Excel и полную очистку с подтверждением.

Видеопоток и калибровка всегда используют полный кадр. ROI ограничивает только обнаружение маркера, сохраняется отдельно для каждой камеры/backend/разрешения и не сбрасывает действительную калибровку.

После первого успешного подключения приложение запоминает индекс камеры, backend и фактическое разрешение. При следующем запуске можно подключиться без полного сканирования. Кнопка **Обновить камеры** запускает полный поиск, если состав устройств изменился. Время открытия, настройки и получения первого кадра записывается в `%LOCALAPPDATA%\MarkerQC\logs\marker_qc.log`.

## Работа оператора

- Красные L1/L2 задают длину.
- Синие W1/W2/WC задают перпендикулярный размер ширины.
- Тонкая жёлтая рамка показывает текущую область поиска.
- При неверных точках нажмите **Коррекция точек**: кадр заморозится, а изображение можно увеличить.
- Если маркер исчез, касается границы ROI или обнаружено несколько кандидатов, размеры очищаются и сохранение блокируется.
- **Очистить историю** удаляет измерения и только связанные снимки внутри управляемого каталога. Калибровка и настройки сохраняются.

Пользовательские данные находятся вне каталога установки: `%LOCALAPPDATA%\MarkerQC`.

## Разработка на Windows

Требуется Python 3.12 x64.

```powershell
git clone <repository-url>
cd CamCan
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run_marker_qc.py
python -m pytest -q
```

Локальная onedir-сборка:

```powershell
.\build.ps1
```

Результат: `dist\MarkerQC\MarkerQC.exe`. Для упаковки версии 1.1.1:

```powershell
.\scripts\package_release.ps1 -Tag v1.1.1
```

Скрипт проверяет совпадение тега с `pyproject.toml`, создаёт ZIP и SHA-256 в `release\`.

Локальные сборки удаляются при необходимости обычным удалением игнорируемых каталогов `build\`, `dist\` и `release\`. Не удаляйте `%LOCALAPPDATA%\MarkerQC`, если нужно сохранить историю и калибровку.

## GitHub Actions и выпуск версии

- `.github/workflows/ci.yml` запускает компиляцию модулей и тесты на Windows при push и pull request.
- `.github/workflows/release.yml` автоматически запускается для нового тега `v*`; его также можно повторно запустить вручную через `workflow_dispatch`, указав существующий тег. Workflow проверяет версию, выполняет тесты, собирает onedir, запускает frozen smoke test, создаёт ZIP и SHA-256 и публикует GitHub Release.
- Публикация использует штатный `GITHUB_TOKEN` с `contents: write` только в release job. Pull request не может опубликовать релиз.
- Существующий релиз с тем же тегом не перезаписывается.

Создание релиза:

```powershell
git tag v1.1.1
git push origin v1.1.1
```

Ручной эквивалент после локальной сборки и упаковки:

```powershell
gh release create v1.1.1 release\MarkerQC-Windows-x64.zip release\MarkerQC-Windows-x64.zip.sha256 --verify-tag --generate-notes
```

Не храните персональные токены в репозитории.

## Linux: запуск из исходников

Windows EXE не предназначен для непосредственного запуска на Linux. Используйте исходный код и Python 3.12–3.15:

```bash
git clone <repository-url>
cd CamCan
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python run_marker_qc.py
python -m pytest -q
```

Камера должна быть доступна как UVC/V4L2-устройство, обычно `/dev/videoN`. Пользователю могут потребоваться членство в группе `video`, правила udev и установленные системные библиотеки Qt/XCB. В Linux приложение использует автоматический backend OpenCV; индекс устройства может отличаться от Windows.

Локальная Linux-сборка создаётся только на Linux:

```bash
python -m PyInstaller --noconfirm --clean MarkerQC.spec
```

PyInstaller не создаёт корректный Windows EXE обычным запуском на Linux.
